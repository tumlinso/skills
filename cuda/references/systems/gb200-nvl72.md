# GB200 NVL72 System Route

Use this route when the deployment or scale target is **GB200 NVL72** rather
than the native V100 host.

NVIDIA documents GB200 NVL72 as a rack-scale system with a **72-GPU NVLink
domain** and a Grace-Blackwell design, including 18 compute trays and 9 NVL72
NVLink switch trays in the 72x1 reference configuration:
https://docs.nvidia.com/multi-node-nvlink-systems/index.html
https://docs.nvidia.com/multi-node-nvlink-systems/multi-node-tuning-guide/system.html

## System Doctrine

1. Separate kernel tuning from rack-scale communication tuning.
2. Do not carry native V100 topology assumptions into GB200.
3. Treat communication-library behavior, benchmark representativeness, and
   system services as first-class concerns.
4. Keep deployment builds narrow to the Blackwell path first, then add fallback
   compatibility only where required.

## System Facts To Respect

- 72 GPUs live in one NVLink domain on the 72x1 reference rack.
- Compute, switch, and service networks are separate concerns.
- NVLink management and telemetry are part of the system behavior surface.
- Benchmarking must reflect deployment message sizes and collective structure,
  not only single-node kernels.

## Use This Route For

- Blackwell deployment planning
- NCCL and large-collective behavior on GB200
- build-target choices for B100/B200 or GB200 deployment
- deciding whether a native V100 benchmark says anything useful about the rack
