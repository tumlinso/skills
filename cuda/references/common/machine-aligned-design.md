# Machine-Aligned Design

Use this guide when an operation has enough structure, reuse, or communication cost that the ordinary library or SIMT mapping may leave a meaningful design choice open. The goal is to find a representation that makes the required computation native to the machine while preserving the scientific contract. This is candidate generation and disciplined rejection, not a claim that unusual mechanisms are faster.

For routine dense operations already expressed well by cuBLAS/cuBLASLt, cuSPARSE, CUB/CCCL, or another library, start with that route. Do not add circuit-bending steps when they cannot change the dominant cost or useful work.

## Start from the semantic unit

Before choosing a thread, warp, tile, or instruction, write down the smallest operation that must remain correct: the equation or state transition, input domain, output contract, invariants, representative shape and distribution, precision tolerance, and reuse. Keep an independent reference or equation as the correctness oracle, then identify the strongest implementation as the performance baseline. For scientific workloads, preserve the actual operator: a convenient reshape or padded tile does not establish which dimensions are independent or coupled.

Then ask which relationships can become native operations through encoding, layout, and ownership. A semantic unit might be an element, category, graph vertex, bit, lane, register slot, MMA coordinate, owner device, or address. For example, set overlap is word AND plus population count per pair; a fixed lookup can become a lane shuffle; independent small products can occupy one tensor collective. These are candidate mappings of particular operators, not general substitutions.

## Map representation to execution

For each candidate, trace the representation through its lifetime. Specify the producer's output layout and consumer's input layout together; preserve an ownership map across stages when that avoids a canonical store, reload, or transpose. Count conversions, padding, decode, allocation, code size, and lost sparsity. Bit, byte, word, lane, warp, fragment, memory transaction, page, and device are distinct granularities; a useful algorithm states how its semantic unit maps across each boundary.

Treat lane and fragment identity as physical wiring. A shuffle needs a participating source lane and a value present in the expected register; moving multiple words costs multiple exchanges. Explicit Volta PTX fragment maps describe only their documented instruction form. Opaque WMMA layouts must remain opaque unless separately established. Tensor reshaping preserves the operator only if the equation and ownership mapping do. The atlas's [R05 fragment contract](../architectures/volta/v100_atlas/reference/R05-tensor-geometry-and-native-register-interfaces.md) and [E09 ownership evidence](../architectures/volta/v100_atlas/experiments/E09-mma-lane-and-register-ownership.md) illustrate that distinction.

Concurrency proposals need a scope and progress proof. Name required participants, visibility, ordering, queue bounds, and how producers continue while consumers wait. State the merge algebra too: duplicate or reordered updates are safe only when the operator and the algorithm make them safe. Warp, CTA, device, peer, host, copy-engine, and firmware scopes are different contracts. A resident consumer must leave resources for its producer; independent thread scheduling does not prove fairness. For cross-device work, remote pointers do not create remote shared memory, and a request/response protocol is not free. See [R06](../architectures/volta/v100_atlas/reference/R06-participation-visibility-and-progress.md) for synchronization constraints and [R07](../architectures/volta/v100_atlas/reference/R07-nvlink-pcie-and-numa-as-information-boundaries.md) for the communication boundary.

## Compare complete cost and evidence

Model the complete representation path: encode or pack, critical schedule, synchronization, communication, decode or extraction, plus allocation and setup when the workload pays them. Reuse helps only when the repeated saving exceeds conversion, maintenance, and lifetime cost. Overlap independent required work only when shared issue, registers, memory, power, and other resources do not erase the gain. For remote data, compare startup plus payload plus owner service against local staging and owner-compute. Graphs can reduce launch overhead; they do not remove HBM passes. The atlas's [R11 cost model](../architectures/volta/v100_atlas/reference/R11-performance-model-for-circuit-bending.md) and [R14 composition map](../architectures/volta/v100_atlas/reference/R14-composition-conflict-and-scope-map.md) give the governing comparisons.

Require a falsifier for each unconventional candidate and state what result would reject it. Exact encodings need range, carry, extraction, and exceptional-value proofs. Approximate arithmetic needs an explicit domain and error contract; a screen-and-refine path needs a valid error bound and a measured ambiguity rate. A finite test's maximum error is an observation, not a global bound. Adapt only when expected future savings (`q × per-use saving`) exceed observation, switching, repacking, and uncertainty. [R15](../architectures/volta/v100_atlas/reference/R15-numerical-contracts-for-unconventional-arithmetic.md) covers numerical contracts; [C39](../architectures/volta/v100_atlas/compositions/C39-a-representation-changing-search-procedure.md) gives a candidate-generation pattern.

Keep evidence local to the claim. Source/API availability, architectural eligibility, measured behavior, and access level are separate axes. A documented primitive may still be a poor fit; a reverse-engineered or firmware-only lead is not a public application contract. Verify public API and target eligibility before implementation. Treat the V100 atlas as V100-specific evidence and hypothesis generation, not as a guarantee for another architecture. Restricted experiments E04 and E27–E30 remain unrun; preserve that status.

The dated GPU runs are bounded overlays, not universal outcomes. [E11](../architectures/volta/v100_atlas/experiments/E11-tensor-versus-bitset-intersections.md) found packed AND+POPC lowest for the tested complete 16×16 intersection outputs, but actual iterations stayed at one, so repeated-query reuse was not measured. [E12](../architectures/volta/v100_atlas/experiments/E12-tensor-circuits-versus-structured-simt.md) tested four independent 4-variable blocks, not a coupled 16-variable operator or `M^r x`. For [E39](../architectures/volta/v100_atlas/experiments/E39-complete-composition-usefulness.md), native arithmetic generally led the selected full-adder cells; the one lower bitplane median had a 95% interval crossing zero, so there is no established crossover. Bitplanes pack independent scalar instances; they do not accelerate a dependent carry chain by definition. [E23](../architectures/volta/v100_atlas/experiments/E23-vmm-alias-and-view-behavior.md) measured about 5× for a device walk against a serial modulo ring on the same rounded 2 MiB domain; it did not isolate modulo as the cause and lacked an optimized mask baseline. [E16](../architectures/volta/v100_atlas/experiments/E16-persistent-roles-and-residency.md) found its resident path slower than finite batching and graph replay for the selected task stream. [E25](../architectures/volta/v100_atlas/experiments/E25-feedback-cost-and-regret.md) found observation cost dominated its synthetic phase schedule. [E20](../architectures/volta/v100_atlas/experiments/E20-actual-nvlink-routing-and-saturation.md) measured directed-copy costs without proving the physical route causing them. [E26](../architectures/volta/v100_atlas/experiments/E26-texture-and-sfu-approximation.md) reports finite-sample error, not global bounds. Open only the measured card that bears on the current candidate.

Promote a candidate through semantic tests, legal compilation, generated-code inspection when it answers a concrete question, isolated measurement, interference measurement, and complete-workload comparison against the strongest baseline. PTX/SASS inspection remains explicit-request-only; follow the [low-level route](../low-level/ptx.md). Report the exact workload, independent oracle, reuse, conversions, precision contract, topology, and evidence limit. Keep failed shapes as boundaries that improve the next decision; do not turn a hypothesis or one dated win into an architecture rule.
